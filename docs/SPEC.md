# Plugcam — ТЗ

> Название выбрано 26.09.2026. На GitHub нашёлся только один пустой репозиторий с таким именем; домены и товарные знаки не проверялись.
>
> **26.09.2026:** этап 0 пройден, ТЗ поправлено по его итогам. Подробности в [stage0.md](stage0.md).

**Цель:** бесплатная программа для Windows с открытым кодом. Она превращает камеру Android-телефона в обычную веб-камеру: подключил телефон, нажал одну кнопку — и в Zoom, Discord, Telegram, OBS или браузере появилась камера «Plugcam Camera». Без OBS, водяных знаков и отдельного приложения на телефоне.

**Для кого:** в первую очередь для автора (OnePlus 11R, Windows 10/11), затем для всех, кому DroidCam, Iriun и подобные надоели ограничениями бесплатных версий.

---

## 1. Главные решения

### 1.1. Приложение на Android не нужно (в первой версии)

Телефон не требует отдельного приложения. Программа на ПК сама загружает на телефон маленький серверный файл из проекта [scrcpy](https://github.com/Genymobile/scrcpy) (`scrcpy-server`, ~0,7 МБ, лицензия Apache-2.0) и запускает его через ADB — отладочный мост Android. Этот файл сам захватывает камеру, аппаратно сжимает видео в H.264 и отдаёт поток на ПК. После отключения файл удаляется с телефона.

Почему так:

- качество и задержка как у scrcpy: аппаратный кодировщик и 1080p. 60 кадров/с берём из обычного режима камеры, где он есть (см. 1.5);
- не нужно писать, подписывать и обновлять APK;
- не нужно давать приложению разрешение на камеру и следить, чтобы Android не усыплял его в фоне.

Цена решения:

- на телефоне один раз включается «Отладка по USB» в режиме разработчика;
- захват камеры в scrcpy работает только с **Android 12+**. OnePlus 11R подходит, это проверено на этапе 0;
- протокол scrcpy внутренний и меняется между версиями, поэтому версия серверного файла **жёстко закреплена** (см. 1.4).

Когда приложение для Android может понадобиться (не в первой версии):

- работа вообще без режима разработчика;
- экран на телефоне с кнопками и предпросмотром;
- ручная экспозиция, фокус и баланс белого: scrcpy этого не умеет.

### 1.2. Программа для ПК: Tauri 2 + Rust

- Внешний вид — Tauri 2 (сейчас `tauri 2.11.x`): окно на системном WebView2, интерфейс на HTML/CSS/TS. Установщик получается на единицы мегабайт; для сравнения, KairoMirror на Electron весит 114 МБ.
- Вся работа с видео, ADB и виртуальной камерой — на Rust, без Node и Python во время работы.
- Интерфейс: Svelte или обычный TS без фреймворка. React для трёх экранов избыточен.
- Почему не WinUI 3: интерфейс там красивее «из коробки», но сборка, упаковка и C#/C++ — это больше трения, чем пользы для такой маленькой программы. Если позже захочется идеальной «виндовости», интерфейс можно переписать, а ядро на Rust оставить.

### 1.3. Виртуальная камера: форк Softcam

- Для первой версии берём [Softcam](https://github.com/tshino/softcam) (MIT, обновлялся 17.09.2026). Это DLL-фильтр DirectShow: одной функцией создаёшь камеру, другой отправляешь кадры (`scCreateCamera`, `scSendFrame`).
- **Форк обязателен.** В оригинале жёстко прописаны имя камеры `DirectShow Softcam`, идентификатор класса (CLSID) и имена общей памяти. Если на компьютере стоит другая программа на Softcam (например, VCamdroid), они будут мешать друг другу. В форке меняем:
  - имя камеры на `Plugcam Camera`;
  - CLSID на новый GUID;
  - имена мьютекса и общей памяти (`FrameBuffer.cpp`: `NamedMutexName`, `SharedMemoryName`).
- Формат кадра: 24-битный BGR, строки сверху вниз (переворачивает сам Softcam). Ширина и высота должны делиться на 4.
- Размер камеры задаётся при создании. Чтобы сменить разрешение, камеру нужно пересоздать, и видеосвязь может переоткрыть устройство. Поэтому по умолчанию камера всегда отдаёт **1920×1080**, а картинка с телефона вписывается в кадр с чёрными полями, если пропорции не совпадают.
- Ограничение DirectShow: камеру видят Zoom, Discord, Telegram Desktop, OBS, Chrome/Edge и большинство десктопных программ. **Не видят** приложения из Microsoft Store, в том числе встроенная «Камера», новые Teams и Windows Hello. Это решается во второй версии через виртуальную камеру Media Foundation (`MFCreateVirtualCamera`, Windows 11), но там нужен отдельный COM-источник видео — работы заметно больше.

### 1.4. Зависимости, которые кладём в установщик

### 1.5. Камеры и режимы берём у телефона (по итогам этапа 0)

- Список камер и режимов программа получает от телефона (`list_cameras`, `list_camera_sizes`) и запоминает для каждого устройства. Жёстко прописанных режимов нет.
- 60 кадров/с берём из обычной сессии камеры, если она их перечисляет (не выше 1080p: список FPS общий на все размеры).
- На многих телефонах обычный режим отдаёт до **30 кадров/с**, а 60 есть только через high-speed-режим (`camera_high_speed=true`, `camera_fps=120`): на OnePlus 11R 1080p120 даёт на ПК ≈ 60 кадров/с. В такой сессии Android сам ведёт AE/AWB/AF и ставит постобработку FAST, выдержка не длиннее 1/120 с: цвета проще, в темноте шумно, под лампами 50 Гц мерцает. Поэтому high-speed выключен по умолчанию и включается только отдельной настройкой.
- Некоторые камеры в списке не работают. На OnePlus 11R логическая камера 4 (зум от 0,5) отвечает `Camera capture failed` на каждом кадре. Если камера не отдала первый кадр за несколько секунд, программа запоминает её как нерабочую для этого телефона и скрывает из выбора.

## 2. Как это работает

```
Телефон (Android 12+)                        ПК (Windows 10/11)
┌──────────────────────┐   ADB (USB/Wi-Fi)  ┌────────────────────────────────────┐
│ scrcpy-server 4.1    │ ─────────────────► │ Rust-ядро                          │
│ Camera2 → MediaCodec │   H.264 + заголовки│  1. разбор потока scrcpy           │
│ (аппаратный H.264)   │ ◄───────────────── │  2. декодер H.264 Media Foundation │
│                      │   команды: фонарик,│  3. NV12 → BGR, масштаб, поля      │
└──────────────────────┘   зум              │  4. Softcam → «Plugcam Camera»     │
                                            │  5. уменьшенный предпросмотр → UI  │
                                            └────────────────────────────────────┘
```

### 2.1. Запуск сервера (по документации scrcpy 4.x, раздел Server/Protocol)

0. Завершить старый процесс сервера, если он остался: `adb shell pkill -f com.genymobile.scrcpy.Server`. Если он был, подождать ~3 с. На этапе 0 после упавшей сессии камеры отвечали `Too many other clients connecting`, пока старый сервер не завершили.
1. `adb push scrcpy-server /data/local/tmp/plugcam-server.jar`
2. Туннель: `adb reverse localabstract:scrcpy_<SCID> tcp:<свободный_порт>`; если не вышло — `adb forward tcp:<порт> localabstract:scrcpy_<SCID>`. `SCID` — случайное 31-битное число в шестнадцатеричном виде (`%08x`).
3. `adb shell CLASSPATH=/data/local/tmp/plugcam-server.jar app_process / com.genymobile.scrcpy.Server 4.1 scid=<SCID> log_level=info video_source=camera audio=false control=true cleanup=true camera_facing=back camera_size=1920x1080 camera_fps=30 video_codec=h264 video_bit_rate=<битрейт>`
   Для прямого туннеля добавить `tunnel_forward=true`.

Параметры, которые нужны программе: `camera_id`, `camera_facing`, `camera_size`, `camera_ar`, `camera_fps`, `camera_high_speed`, `camera_zoom`, `camera_torch`, `capture_orientation`, `angle`, `video_bit_rate`, `list_cameras`, `list_camera_sizes`.

### 2.2. Протокол (scrcpy 4.x, внутренний — закреплён версией)

- Сокеты открываются по порядку: видео, затем управление; звук отключён.
- При прямом туннеле на первом сокете сначала приходит 1 пустой байт.
- Затем на первом сокете идёт имя устройства: 64 байта UTF-8 с нулями в конце.
- На видеосокете приходит кодек (`u32`, `0x68323634` = h264).
- Пакет сессии (12 байт; старший бит = 1) содержит ширину и высоту (`u32`); младший бит байта 3 — флаг «клиент изменил размер», для камеры не используется. Для камеры сессия не меняется при повороте телефона: поворот задаётся только параметром `capture_orientation`.
- Пакет кадра — заголовок 12 байт: старший бит = 0 (медиа-пакет), бит 62 = настройки кодека, бит 61 = ключевой кадр, остальные 61 бит — время кадра (PTS, мкс); затем `u32` размер и данные H.264 в формате Annex B. У пакета настроек кодека вместо PTS стоит только флаг.
- Управление — один байт типа и данные: `18` = фонарик (+ `bool`), `19` = приблизить, `20` = отдалить. Эти номера сверены с `ControlMessage.java` в v4.1.

### 2.3. Декодирование и отдача кадров

- Используем декодер H.264 Media Foundation, встроенный в Windows: крейт `windows`, `CLSID_CMSH264DecoderMFT`, режим `CODECAPI_AVLowLatencyMode`, на выходе NV12. Если декодер вернул `MF_E_TRANSFORM_STREAM_CHANGE`, заново согласовываем формат выхода.
- FFmpeg не используем: он добавит десятки мегабайт.
- Преобразование NV12 → BGR — `yuvutils-rs`, масштабирование — `fast_image_resize`. Кадр вписывается в размер камеры с чёрными полями, зеркалирование делается здесь же.
- Сенсор камеры альбомный: в портретном положении телефона кадр 1920×1080 приходит повёрнутым (этап 0). Поворот делается на телефоне (`capture_orientation`), по умолчанию 0 — для телефона, закреплённого горизонтально. С поворотом 90/270 кадр 1080×1920 вписывается в камеру с полями по бокам.
- Цвет берётся из выхода декодера (`MF_MT_VIDEO_NOMINAL_RANGE`, `MF_MT_YUV_MATRIX`): без поворота OnePlus 11R шлёт full-range BT.601, с поворотом — limited range. Жёстко не задаём.
- В Softcam создаём камеру с частотой кадров `0` и отправляем каждый кадр сразу, без искусственной задержки.
- Предпросмотр в окне: уменьшенная копия ~640 px, не чаще 15 кадров/с, JPEG через `tauri::ipc::Channel` сырыми байтами → `<canvas>`. Если окно свёрнуто, предпросмотр не считается.

### 2.4. Wi-Fi

Всё на встроенной беспроводной отладке ADB, на телефон ничего не ставится (`src-tauri/src/wifi.rs`). Окно «Телефоны и Wi-Fi» в боковой панели предлагает три способа.

1. **QR-код (Android 11+).** Программа показывает QR `WIFI:T:ADB;S:plugcam-<8 символов>;P:<10 символов>;;` — формат Android Studio. Пользователь сканирует его в «Отладка по Wi-Fi → Подключить устройство с помощью QR-кода». Программа ждёт службу `_adb-tls-pairing._tcp` с этим именем в `adb mdns services`, выполняет `adb pair`, затем находит `_adb-tls-connect._tcp` и делает `adb connect`.
2. **Код сопряжения (Android 11+).** Шесть цифр из «Подключить устройство с помощью кода». Адрес телефона программа ищет через mDNS сама; если сеть его не показывает, пользователь вводит IP:порт, который телефон показывает рядом с кодом.
3. **С кабеля.** Телефон подключён кабелем и сидит в той же сети: `adb tcpip 5555`, IP телефона из `ip addr show wlan0` (запасной вариант — `ip route`), `adb connect ip:5555` (до 6 попыток). Соединение не шифруется и живёт до перезагрузки телефона — интерфейс об этом предупреждает.

Ещё есть «Подключиться по адресу» — для сопряжённого телефона, которого не видно через mDNS (гостевые сети, изоляция клиентов).

**VPN на телефоне.** С включённым VPN телефон часто не объявляет `_adb-tls-connect._tcp`, а экран «Отладка по Wi-Fi» показывает адрес VPN (например `26.26.26.1:37075`), до которого ПК не достучаться; порт при этом верный. Поэтому:

- если после сопряжения телефон не нашёлся, окно открывает «Подключиться по адресу» с уже подставленным Wi-Fi-IP, на котором прошло сопряжение (`<ip>:`), — остаётся ввести порт с телефона;
- если `adb pair`/`adb connect` по введённому адресу не удались, программа пробует тот же порт на других IP этого телефона: у службы mDNS того же типа с тем же портом, у сопряжённого в этом сеансе телефона и у телефона на кабеле (если он один или его серийник есть в mDNS-имени сопряжения). Каждая попытка ограничена 5 с;
- в подсказках: VPN на телефоне прячет его и показывает не тот адрес — взять Wi-Fi-IP из «О телефоне → Статус» или выключить VPN на время сопряжения.

**Выбор телефона.** По умолчанию берётся первый готовый, USB раньше Wi-Fi. Можно закрепить конкретный телефон; выбор передаётся в конвейер явно. Wi-Fi-телефон запоминается по постоянному id (mDNS-имя `adb-…`, для «с кабеля» — `ip:5555`), а не по серийнику `ip:порт`: порт меняется при каждом перезапуске отладки, и программа каждый раз находит текущий серийник по id. `adb devices -l` разбирается с учётом пробелов в mDNS-именах (`adb-XXXX (2)._adb-tls-connect._tcp`). Сопряжённые телефоны запоминаются в настройках; телефон, которого нет в сети, показан как «не в сети», и программа подключает его, когда он появится. «Забыть» отключает телефон, переводит камеру на другой и больше его не подключает и не выбирает автоматически (список забытых id хранится в настройках и переживает перезапуск; телефон возвращается, если его выбрать или добавить снова), но сопряжение не снимает: для этого на телефоне нужно удалить ПК в «Отладка по Wi-Fi → Сопряжённые устройства» (окно об этом говорит).

**Поток по Wi-Fi** (`pipeline.rs`):

- ключевой кадр каждую секунду (`video_codec_options=i-frame-interval=1`), чтобы догнать поток можно было меньше чем за секунду;
- стартовый битрейт 6 Мбит/с (или меньше, если пользователь задал меньше). После зависания (если телефон при этом отвечает) или частых догонов следующая сессия получает 0,7 от битрейта, но не меньше 2 Мбит/с; после 5 минут трансляции без проблем следующая сессия получает шаг обратно, но не выше стартового;
- **догон:** программа сравнивает время кадра (PTS) со временем прихода. Если картинка отстала больше чем на 500 мс, кадры пропускаются до ключевого, пока отставание не упадёт до 250 мс. Пропуск длится не дольше 3 с: если не успевает сам ПК, новая задержка принимается за норму, а не догоняется бесконечно. Три догона за минуту означают, что сеть не тянет битрейт, и он понижается;
- таймауты длиннее, чем по USB: первый кадр — 10 с (USB — 6 с), зависание — 5 с (USB — 3 с). «Нет картинки» (камера не отдаёт кадры) отличается от сетевой задержки: по Wi-Fi пустой старт считается проблемой сети, если в логе сервера нет ошибки камеры.

**Переподключение.** Если поток оборвался, программа проверяет телефон `adb shell echo ok` (4 с): мёртвое Wi-Fi-соединение долго висит в списке как `device`. Если телефон не отвечает — `adb disconnect`, 3 с ждём, что adb переподключит mDNS-телефон сам, потом ищем текущий адрес через mDNS (порт меняется при каждом перезапуске отладки) и делаем `adb connect`. До 5 попыток, статус «Переподключение по Wi-Fi (N из 5)»; `adb connect`/`disconnect` здесь ограничены 5 с, а остановка камеры прерывает переподключение между шагами. Если телефон вернулся под другим серийником (mDNS-имя → `ip:порт`), конвейер сообщает об этом: id телефона переносится на новый серийник, и выбранный телефон (он хранится по id) находится под ним; конвейер переходит на новый серийник, только если шёл именно этот телефон. При переходе на другой телефон битрейт и счётчик неудач начинаются заново. Сессии короче 10 с считаются неудачными: вторая подряд показывает ошибку, паузы растут 2 → 4 → 8 → 15 с. Виртуальная камера всё это время отдаёт последний кадр, поэтому видеосвязь не теряет устройство.

**Подсказки про сеть** в окне: одна сеть у ПК и телефона (5 ГГц плавнее), «Всегда разрешать в этой сети», гостевые сети и изоляция клиентов, раздача интернета с телефона не подходит, разрешить adb.exe в брандмауэре для частных сетей.

## 3. Интерфейс (минимум кнопок)

**Главный экран — одно окно примерно 420×560, тёмная и светлая тема как в системе, фон Mica на Windows 11:**

- Карточка телефона: модель, способ подключения (USB или Wi-Fi) и цветной статус (по Wi-Fi ещё «Переподключение»): «Подключите телефон» / «Готово» / «Идёт трансляция» / «Ошибка — что делать».
- Большой предпросмотр.
- **Одна главная кнопка:** «Включить камеру» / «Выключить».
- Под ней ряд небольших переключателей: основная/фронтальная камера (плюс выбор объектива, если их несколько; нерабочие камеры скрыты, см. 1.5), зеркало, фонарик, зум − / +.
- Качество: разрешение (720p / 1080p по умолчанию / 1440p / 4K) и частота кадров (30 / 60). Доступны только размеры, которые объектив снимает без масштабирования, и 60 кадров/с, только если камера их реально даёт (см. 1.5). Разрешение одно и для съёмки, и для виртуальной камеры.

**Настройки (шестерёнка):**

- «60 кадров/с через замедленную съёмку» (high-speed): видно только на телефонах без обычных 60 кадров/с, по умолчанию выключено;
- поворот картинки: 0 / 90 / 180 / 270;
- битрейт: «Авто» или ползунок 4–40 Мбит/с;
- «Запускать вместе с Windows» и «Сворачивать в трей»;
- «Автоматически включать камеру при подключении телефона».

**Первый запуск:** мастер из 3 шагов с картинками: включить режим разработчика → включить отладку по USB → подключить кабель и разрешить доступ на телефоне. Можно пропустить и выбрать подключение по Wi-Fi.

**Значок в трее:** включить/выключить камеру, открыть окно, выйти.

**Дизайн:** ориентир — Fluent/Windows 11. Системный шрифт Segoe UI Variable, скругления 8 px, один акцентный цвет, без перегруза. Все надписи на русском и английском, язык по системе.

## 4. Что НЕ делаем в первой версии

- Звук с телефона. Нужен виртуальный микрофон, а это отдельный драйвер.
- macOS и Linux. На Linux и так есть `scrcpy --v4l2-sink`.
- iPhone.
- Ручная экспозиция, фокус и баланс белого: scrcpy этого не даёт.
- Эффекты, фон, размытие, запись видео.
- Виртуальная камера Media Foundation — это вторая версия.
- Подключение через интернет.

## 8. Риски

1. **Захват камеры через scrcpy работает не на всех телефонах.** Есть открытая проблема с ошибкой `Given calling package android does not match caller's uid 2000` ([#4969](https://github.com/Genymobile/scrcpy/issues/4969)). У OnePlus старые ошибки ([#4392](https://github.com/Genymobile/scrcpy/issues/4392), [#4457](https://github.com/Genymobile/scrcpy/issues/4457)) закрыты ещё в 2023 году. **На OnePlus 11R (Android 15) ошибки нет, захват работает.**
2. **Протокол scrcpy меняется.** Решение — закреплённая версия и контрольная сумма серверного файла, а также тесты на записанных потоках.
3. **Экран телефона.** У некоторых телефонов экран сам включается при захвате камеры ([#5404](https://github.com/Genymobile/scrcpy/issues/5404)). **На OnePlus 11R экран не включается, захват при заблокированном экране работает.**
4. **DirectShow не видят приложения из Microsoft Store.** Об этом прямо пишем в README, исправляем во второй версии.
5. **Драйвер ADB на Windows.** Обычно ставится через Центр обновления; если нет — мастер первого запуска даёт ссылку на драйвер.
6. **Лицензии.** scrcpy — Apache-2.0, Softcam — MIT, `adb` — условия Android SDK. Всё перечислить в `THIRD_PARTY_NOTICES.md`.
7. **Нерабочие камеры и зависшие сессии** (этап 0). Часть камер из списка не отдаёт кадры, а упавшая сессия на время блокирует все камеры. Решение: завершать старый сервер перед запуском (2.1) и скрывать нерабочие камеры (1.5).
